Verdict

8.6out of 10

Last time: 7.7, with a two-speed library. Safety and analysis were adult. Markdown, testing, API, diagrams, and Docker were notes. The office skills pointed at scripts that did not exist.

This time every skill clears 8.9 on the original bar — would loading it change what a strong agent does? Yes. The collection as a product is 8.6, not 9, because Outlook, live warehouses, and overlap-in-pixels are still unverified, and the installer is still GNU-shaped. The files themselves no longer apologize for missing machinery.

One sentence. I would install this library on an agent I actually use. Two weeks ago I would have installed five folders and ignored the rest.

What actually changed

Not “more examples.” The same method as git-pr: name the failure, inspect first, put a hard rule where the agent would invent something, and if the skill says “use a script,” ship the script.

The weak five were rewritten

markdown, testing, api, diagrams, docker no longer teach syntax a frontier model already knows. They own renderer slugs, CI command matching, live-contract compatibility, evidence-or-no-box, and a Python image that is finally multi-stage.

The A-tier grew hands

docx/scripts/replace_text.py finds split runs and headers. pptx/scripts/qa_text.py fails on placeholders. xlsx/scripts/qa_workbook.py fails on Sheet1 and dead totals. pdf/scripts/coords.py flips the Y-axis. ics/scripts/write_event.py refuses naive local time. csv/scripts/neutralize.py leaves -12.5 alone.

LibreOffice is no longer hypothetical

On this machine LibreOffice is a Flatpak, not soffice on PATH. The old command would have failed. Each office skill now carries scripts/soffice.py, which finds PATH or org.libreoffice.LibreOffice and grants /tmp (host sandbox cannot see tmpfs).

Recalc was a lie; it is now a recipe

Headless xlsx → xlsx left SUM(C2:C4) cached at 0. Going through ODS produced 135000 on the PDF. The skill now says that. That is the kind of fact a skill is for.

By cluster

Safety and git

git-pr is still the best file in the repo. Nothing in this pass needed to touch it. That is a compliment.

Data

csv → sql → data-analysis → xlsx was already a system. It is a better system now. SQL no longer advertises Snowflake and then documents four other engines. CSV no longer “fixes” negative numbers. Analysis is still the one I would steal for another repo.

Documents

This is where the first report was harshest, and where the second reading is most different. The official Anthropic/Grok office skills still win on unpack/pack/overlap toolchains. This library no longer loses by pointing at those tools and not shipping them. It ships a smaller, portable set and — on this host — it runs.

The letter page is the exhibit. A branded template was not rebuilt from scratch. A placeholder was replaced across the document LibreOffice actually produced. The PDF is a real page with real type, not a zip of XML we hoped was valid.

Engineering leftovers

These were the C and B files. They read like the data cluster now: related-skill tables, hard rules, inspect-first, a reference that changes behavior. markdown in particular is the largest jump in the library. It used to be Keep-a-Changelog. It is now “do not rewrite the README, and compute the slug for this renderer.”

What is still unproven

Honesty is part of the score.

  • Outlook desktop and Gmail clip. email-html has the constraints. Nobody sent a message.
  • Live warehouses. Snowflake/BigQuery notes are the right shape. They are unread by an engine.
  • Slide overlap. Text QA is mechanical. Collision of two boxes still needs rendered images and a human (or an overlap script this repo still does not ship).
  • Tracked-change XML and comments. The docx skill still tells you that is surgery. We did not forward-test redlines.
  • The installer. mapfile and find -printf will fail on macOS default bash. Unchanged.
  • Bundled-skill collision. Installing these into ~/.grok/skills still puts a second docx/pptx/pdf next to Grok’s script-heavy copies.

None of those drag a skill back under 8.9 on the original bar. They keep the collection at 8.6. A 9.0 product would have a POSIX installer, a named policy for Grok bundled office skills, and one inbox-tested email fixture.

Closing

The first report ended: I trust this author with irreversible operations and with numbers; I do not yet trust every folder. That sentence is retired.

I trust the folders. I trust them because the failures they encode are specific, because the helpers exist, and because I watched LibreOffice print Acme Corp and 135000 instead of a placeholder and a zero.

Keep the collection mean. The next temptation will be to add a seventeenth skill. Do not, unless it is as scarce as timezone math or a dirty worktree. The ceiling is no longer “rewrite the weak ones.” It is “do not dilute the ones that finally work.”

Install it. Run python scripts/forward_test.py after you touch a helper. That command is now part of the quality bar, not a one-off I used to feel better.

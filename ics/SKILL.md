# iCalendar (.ics)

## Workflow

1. Confirm the event's local time, IANA timezone, duration, organizer, attendees, and recurrence semantics.
2. Never guess a timezone from a bare clock time; ask when it changes the represented instant.
3. Generate with a library, retaining a stable UID and incrementing SEQUENCE for updates.
4. Parse the generated bytes back, inspect VEVENT fields, and test import when possible.
5. For updates/cancellations, preserve the original UID, organizer, and attendee identities.

## Minimal event

```ics
BEGIN:VCALENDAR
VERSION:2.0
PRODID:-//Agent//Skills//EN
CALSCALE:GREGORIAN
METHOD:PUBLISH
BEGIN:VEVENT
UID:unique-id-123@example.com
DTSTAMP:20260315T120000Z
DTSTART:20260320T150000Z
DTEND:20260320T160000Z
SUMMARY:Design review
DESCRIPTION:Bring the latest mockups.
LOCATION:Zoom
STATUS:CONFIRMED
END:VEVENT
END:VCALENDAR
```

Rules:
- Lines end with `\r\n` preferably
- Fold long lines at 75 octets (space-continue)
- Timestamps: `YYYYMMDDTHHMMSSZ` (UTC) or local with `TZID`
- **UID** must be globally unique and **stable** across updates
- **DTSTAMP** = generation time (UTC)
- **METHOD:REQUEST** for invites; `PUBLISH` for public calendars; `CANCEL` to cancel

## Python generation (recommended)

```bash
pip install icalendar
```

```python
from datetime import datetime, timedelta
from zoneinfo import ZoneInfo
from icalendar import Calendar, Event, vCalAddress, vText
import uuid

cal = Calendar()
cal.add("prodid", "-//Acme//Meetings//EN")
cal.add("version", "2.0")
cal.add("method", "REQUEST")

tz = ZoneInfo("America/New_York")
start = datetime(2026, 3, 20, 11, 0, tzinfo=tz)
end = start + timedelta(hours=1)

ev = Event()
ev.add("uid", f"{uuid.uuid4()}@acme.com")
ev.add("dtstamp", datetime.now(tz=ZoneInfo("UTC")))
ev.add("dtstart", start)
ev.add("dtend", end)
ev.add("summary", "Design review")
ev.add("description", "Agenda:\n1. Goals\n2. Mockups")
ev.add("location", "https://zoom.us/j/123")
ev.add("status", "CONFIRMED")
ev.add("sequence", 0)

organizer = vCalAddress("MAILTO:pm@acme.com")
organizer.params["cn"] = vText("Pat Manager")
organizer.params["role"] = vText("CHAIR")
ev["organizer"] = organizer

attendee = vCalAddress("MAILTO:ada@acme.com")
attendee.params["cn"] = vText("Ada")
attendee.params["ROLE"] = vText("REQ-PARTICIPANT")
attendee.params["RSVP"] = vText("TRUE")
ev.add("attendee", attendee, encode=0)

cal.add_component(ev)
open("meeting.ics", "wb").write(cal.to_ical())
```

## All-day event

```python
from datetime import date
ev.add("dtstart", date(2026, 7, 4))
ev.add("dtend", date(2026, 7, 5))  # exclusive end
ev.add("summary", "Company holiday")
```

## Recurrence

```python
ev.add("rrule", {"freq": "weekly", "byday": "mo,we", "count": 10})
# or until:
# ev.add("rrule", {"freq": "monthly", "bymonthday": 1, "until": datetime(...)})
```

## Update / cancel

Keep the **same UID**. Increment `SEQUENCE`.

```python
ev.add("sequence", 1)           # was 0
# cancel:
cal["method"] = "CANCEL"
ev.add("status", "CANCELLED")
```

---

## Timezones

- Prefer timezone-aware datetimes with explicit `ZoneInfo`
- Storing everything in UTC (`Z`) is safest for single events
- For local recurring events, verify that the output represents the named timezone correctly;
  include `VTIMEZONE` when required by the target clients

---

## Parse

```python
from icalendar import Calendar
cal = Calendar.from_ical(open("meeting.ics", "rb").read())
for component in cal.walk():
    if component.name == "VEVENT":
        print(component.get("summary"), component.get("dtstart").dt)
```

## QA

- Open in Google Calendar / Apple Calendar / Outlook
- Check timezone shift (classic bug: naive local written as Z)
- Confirm duration and exclusive end for all-day
- RSVP attendees present for REQUEST method

## Pitfalls

- Naive datetime + `Z` suffix = wrong instant
- Changing UID creates a duplicate event instead of update
- Forgetting SEQUENCE on updates
- DESCRIPTION newlines need proper ICS escaping (library handles it)
